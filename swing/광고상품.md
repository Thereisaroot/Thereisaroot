# 광고 상품 기획 정리

## 1. 현재 광고 구조 요약
- **광고 상점(Rewarded Ad)**
  - `wizard` 캐릭터 해금
  - `$20 파우치` 즉시 지급
- **전면+보상형(Interstitial with reward)**
  - `lives` 복구/추가

## 2. 신규 광고 상품 구상
### 2.1 SkillStart 광고 해금
- 기존 아이템 상점 `startskill`과 동일한 효과를 광고 1회 시청으로 영구 획득.
- 재시청 옵션(선택): 광고 재시청 시 해당 런에서 1회 Start Skill 임시 적용.

### 2.2 스킬 카드 슬롯 +1 (영구)
- 목표: 기본 카드 장수를 +1 영구 확장.
- 조건: 10$ → 20$ → 30$ 파우치 광고 순차 시청을 모두 완료해야 해금 버튼 활성화.
- 해금 후 광고 슬롯은 숨김 또는 “완료” 상태로 표시.

## 3. 광고 데이터 구조 제안

광고 상품은 `type` 값으로 노출/활성 조건을 구분하고, 카드 자체는 항상 보이되 버튼 상태만 `enabled/disabled`로 표현합니다.

예시:
```json
{
  "id": "skillstart_ad",
  "label": "Start Skill 해금",
  "type": "single",
  "limit": "once",
  "reward": {
    "key": "start_skill_unlock"
  },
  "done": false
},
{
  "id": "skill_card_plus_unlock",
  "label": "스킬 슬롯 +1",
  "type": "doneCheck",
  "requirements": ["pouch_10", "pouch_20", "pouch_30"],
  "limit": "once",
  "reward": {
    "key": "skill_slot_upgrade"
  },
  "done": false
}
```
- `type: "single"` : 조건 없이 즉시 시청 가능. `done`이 true이면 버튼을 완료 상태로 표시.
- `type: "doneCheck"` : `requirements` 배열에 명시된 광고 상품 ID가 모두 완료되어야 버튼이 활성화.
- UI에서는 카드가 항상 노출되며, requirements 미충족 시 버튼은 `disabled` 상태 + 안내 툴팁/설명 제공.
- 진행도와 완료 여부는 사용자 상태(예: localStorage + 서버 저장)를 기반으로 업데이트.

※ `limit` 필드 예시
- `once`: 영구 해금/1회성 상품 (SkillStart, 스킬 슬롯 +1 등)
- `daily`: 하루 1회 반복 가능(예: 10$/20$/30$ 파우치)
- 필요 시 다른 주기(weekly 등) 확장 가능

## 4. 광고 단위(Placement) 최소화 전략
1. **단일 Rewarded Placement 재사용**
   - AdMob/Unity Ads 등에서는 동일한 rewarded placement를 호출하더라도
     **광고 노출 전 UI에서 명확한 보상 정보를 고지**하면 서로 다른 보상을 순차로 줄 수 있음.
   - 단, 서버 검증(SSV)을 사용할 경우 reward 정보를 각 호출 시 식별 가능하게 보내야 함.
2. **프로그레션 방식**
   - 10$ → 20$ → 30$ 파우치 광고를 **동일 placement**로 쓰되,
     프론트에서 현재 단계에 맞는 보상 설명을 표시하고, 광고 완료 후 해당 보상만 지급.
   - 이렇게 하면 광고 크리에이티브/단위는 1개지만, 내부 로직으로 단계별 보상을 제공 가능.
3. **추가 예시**
   - SkillStart 해금도 같은 placement로 처리하여 광고 단위를 늘리지 않고, 노출 전 UI에서 “SkillStart 해금” 문구를 제공.

## 5. AdMob 정책 체크
- Rewarded 광고는 **노출 전/후 보상 내용이 명확**해야 하며, 시청 1회에 약속된 보상을 정확히 지급해야 함.
- “여러 광고를 순차로 시청해야 추가 보상을 제공”하는 것은 허용되지만,
  - 각 광고는 **단일 보상 단위**를 제공해야 하며,
  - 보상 누적 조건(예: 10$ → 20$ → 30$ 완료 시 스킬 슬롯 +1)은 앱 자체 로직으로 관리.
- 다른 광고 네트워크와 병행할 때도 같은 정책을 적용: 보상 안내와 지급이 일치해야 하며, 미리 고지 없이 보상을 변경하면 정책 위반이 될 수 있음.

## 6. 권장 UX 흐름 및 UI 아이디어
1. 광고 상점 기본 카드 레이아웃
   - Wizard / $20 파우치 / SkillStart / Skill Slot Upgrade 등이 항상 보임
   - 각 카드에는 아이콘, 제목, 현재 상태(가능/진행 중/완료)를 시각적으로 표시
2. 상태 표시 방식
   - `doneCheck` 조건 미충족 시: 버튼은 비활성화 스타일 + “조건 X/Y 달성” 배지
   - 비활성 상태에서 클릭하면 팝업/툴팁으로 “먼저 20$ 파우치를 시청해야 합니다” 등 원인 설명
   - 조건 충족 후: 버튼 활성화 + “광고 보기” CTA 강조
   - `done` 상태(이미 해금) 시: “완료” 리본 또는 체크마크 표시
3. 카드 클릭 시 설명 팝업/모달
   - 보상 설명, 조건 목록, 진행바(아이콘 3개 채우기 등), 예상 보상을 명확하게 안내
   - 광고 실패 시 재시도 안내 / 완료 후에는 “보상 지급 완료” 알림 제공
4. Skill Slot Upgrade 예시 UX
   - 카드 하단에 “파우치 광고 3종 완료 시 해금 가능” 안내
   - 진행도: 10$ → 20$ → 30$ 단계별로 아이콘 채우기(색상 변화 또는 체크)
   - 3개 모두 충족 시 버튼 활성화 → 광고 시청 후 +1 적용 → 카드 상태를 “완료”로 전환
5. SkillStart 예시 UX
   - 초기 상태: “광고 1회 시청으로 Start Skill 영구 해금” 설명
   - 시청 후 버튼 비활성화 + “해금 완료” 태그
   - 재시청 기능이 있다면 동일 카드에서 “런당 1회 임시 적용” 같은 옵션 표시
